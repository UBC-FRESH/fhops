# FHOPS v1.1.0

- GitHub release: https://github.com/UBC-FRESH/fhops/releases/tag/v1.1.0
- PyPI: https://pypi.org/project/fhops/1.1.0/

FHOPS 1.1.0 is the first stable release of the 1.1 line. It keeps the corrected 1.0.1 operational
core invariant, stabilises the tactical–operational layer, and adds log hauling, multi-day marine
cycles, the optional web application, and FEMIC LiDAR consumption.

```bash
pip install fhops==1.1.0
# optional browser UI
pip install 'fhops[web]==1.1.0'
# optional LiDAR/Bundle tooling
pip install 'fhops[lidar]==1.1.0'
```

## Highlights

### Operational core

- The FHOPS 1.0.1 corrections remain the baseline: exact heuristic objectives, landing capacity on
  every shift, sequencing/playback alignment, `Scenario.initial_state`, robust MILP outcomes, and
  the performance-regression fixes.
- Calendar semantics now require both the day and shift calendars (AND), matching formulation E1,
  the heuristics, warm-start derivation, and rolling day locks.
- Earliness-stage exports no longer include fractional phantom assignments; carry-forward role state
  is exact for multi-terminal/staged systems; empty-window handling and solver-limit validation were
  hardened.
- Third-audit heuristic fixes: locked slots may idle without violations, no-compatible-role blocks
  admit no machine, `fhops validate` warns about blocks the fleet cannot work, and synthetic tiers
  use deliverable fleet roles.

### Tactical–operational planning

- Stable tactical–operational contract with periods, products, facilities, transport arcs,
  inventories, purchases, roads, silviculture, and fleet options.
- Aggregate Pyomo/HiGHS MILP with continuous, semi-continuous, and whole-block harvest modes;
  cost, discounted-profit, and NPV objective profiles.
- Scenario overlays, diffs, batch manifests, tactical reports, and operational handoff through
  `plan compile-tactical`.

### Log hauling and marine cycles

- Ghotb-inspired Phase I flow MILP, Phase II/III daily truck/loader scheduling, and the SA/SPT
  solution path.
- Explicit marine transport: barge types, ports, water arcs, port legs, marine routes, marine
  drayage, and barge-cycle scheduling.
- Multi-day marine voyages use explicit arrival lag, in-transit volume, arrival-day port/demand
  timing, and sliding-window barge occupancy. Same-day marine routes are unchanged.
- Stable hauling artefacts/KPIs and the Quatsino → Ladysmith regression fixture.

### Web application

- Optional FastAPI + vanilla ES-module SPA over CLI artefacts, with operational, hauling, tactical,
  and reviewer skins.
- Map/layer tree, shift/day/period controls, operational/hauling/tactical panels, KPIs, reports,
  run comparison, and live CLI runs over SSE.
- Validated scenario editing for objective/locks, hauling driver/contractor fields, and tactical
  demand overlays.
- Read-only reviewer skin, loopback default, optional local assistant (`--allow-agent`, off by
  default), and the Web/LiDAR workflows.
- Map/table polish: workspaces, URL state, accessible tabs, responsive iPad-landscape layout,
  sortable tables, selected-block highlighting, and a colour-blind-aware palette.

### FEMIC LidarBC consumption

- Versioned FEMIC bundle contract with checksums, licence, CRS, native resolution, vertical datum,
  and lineage validation.
- `fhops scenario lidar validate|register|map|operability` for pinning a bundle to a scenario AOI,
  mapping native-resolution terrain/canopy support, and reporting advisory ground/cable/helicopter
  operability with explicit fallbacks.
- Public TFL 6 fixture with WS4/FEMIC parity evidence and a web LiDAR evidence/workflow panel.

## Compatibility and changes

- Existing operational schema `1.0.0` scenarios remain supported; `schema_version: 1.1.0` adds the
  optional hauling section. Tactical–operational scenarios use the separate `0.1.0` contract.
- Operational plan values can differ from 1.0.0 and 1.0.1 where the audit fixes changed a plan; the
  1.0.1 upgrade checklist and release notes still apply.
- `fhops solve-mip`, `fhops build-mip`, and `fhops.optimization.mip.solve_mip` remain deprecated;
  use the operational MILP/heuristic commands.
- The web extra is optional; the core install and CLI are unchanged without it. The web service has
  no authentication and is loopback-only by default. See `docs/howto/web.rst`.
- The LiDAR extra is optional; FHOPS consumes FEMIC bundles and never discovers/materialises source
  LiDAR. Operability thresholds and cost context are planning assumptions.
