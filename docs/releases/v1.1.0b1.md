# FHOPS v1.1.0b1

- GitHub prerelease: https://github.com/UBC-FRESH/fhops/releases/tag/v1.1.0b1
- PyPI: https://pypi.org/project/fhops/1.1.0b1/

## Beta status

FHOPS 1.1.0b1 is a **beta prerelease**. It merges the FHOPS 1.0.1 operational corrections, which
were frozen for the accepted SoftwareX manuscript, into the 1.1.0 tactical–operational line. The
two lines were siblings: `1.1.0a1` was built from a base that predated the 1.0.1 work, so its
operational heuristics scored a different (pre-1.0.1) problem. This release restores the corrected
operational formulation and keeps the tactical layer.

The tactical contract and CLI surfaces remain provisional. Use the beta to evaluate the combined
workflow and report defects or API friction.

## Scope

- Operational planning: the FHOPS 1.0.1 corrections (below).
- Tactical–operational planning: the 1.1.0a1 tactical layer, unchanged in scope.

## The 1.0.1 operational corrections, now in the 1.1 line

- **Exact heuristic objective** and no penalty on idle unavailable slots (#133).
- **Landing guard on every day**, MILP-plan scoring, and override transparency (#142).
- **Heuristics, tracker, and playback fixes** (#121).
- **MILP and playback sequencing alignment**; blackouts enforced in the MILP (#112).
- **`Scenario.initial_state`** for rolling-horizon carry-forward (#97).
- **MILP objective and semantics fixes** (#143), and operational MILP robustness (#122).
- **Landing capacity alignment**, multi-shift day locks, idle locked slots (#132).
- **KPIs for empty and partial plans** (#111), and the heuristic performance-regression fix (#154).
- Higher floors for `pyomo>=6.9.2`, `highspy>=1.8.1`, and `typer>=0.15.4`.

## Performance

- **Simulated annealing, 2.1× faster**, with identical results. The annealing loop evaluated every
  generated neighbour and then used only the first acceptance; it now scores neighbours lazily and
  stops at the first acceptance. Because evaluation draws no randomness, the random stream and every
  run are unchanged.

  Benchmark ladder (200 iterations, seed 42; `python scripts/benchmark_sa.py`):

  | Scenario | 1.1.0a1 (evals/s) | 1.1.0b1 (evals/s) | Objective |
  |---|---|---|---|
  | tiny7 | 281 | 580 | 4295.8 |
  | small21 | 72 | 167 | 15551.1 |
  | med42 | 21.2 | 44.4 | 21141.7 |
  | large84 | 2.2 | 3.4 | −210425.2 |

- The remaining hot path is the per-move repair; an incremental evaluator is future work
  (`notes/sa_performance_plan.md`).

## Compatibility

- Operational scenario bundles and CLI workflows are backward-compatible with the 1.0.x contract;
  the operational corrections change plan values, so 1.0.x regression pins were updated.
- The Phase 5 formulation traceability test now checks the canonical labelled 1.0.1 formulation.
