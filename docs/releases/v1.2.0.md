# FHOPS v1.2.0

- GitHub release: https://github.com/UBC-FRESH/fhops/releases/tag/v1.2.0
- PyPI: https://pypi.org/project/fhops/1.2.0/

FHOPS 1.2.0 adds the tree-scale execution layer, deterministic multi-machine
ground-system simulation, 3D scene export, and the supporting hydrology/docs
work already on `main`.

```bash
pip install fhops==1.2.0
# optional web UI
pip install 'fhops[web]==1.2.0'
# optional DEM/road and LiDAR tooling
pip install 'fhops[lidar]==1.2.0'
```

## Highlights

### Tree-scale inventory and stem execution

- `fhops.tree.inventory.v1` contract with metadata, checksums, CRS, provenance,
  and fail-closed validation.
- Scenario inventory pin, live-tree block maps, density and volume-proxy
  reconciliation.
- Pluggable stem model with a reference form-factor volume/bucking scaffold,
  per-tree logs, products, and block totals.
- Single-machine spatial simulation with reach, terrain slope, obstacles, and
  deterministic per-tree events.
- Schedule replay with tree consumption, leftovers, and scheduled-versus-
  simulated discrepancies.
- `fhops tree inventory validate`, `register`, `map`, `stems`, `simulate`,
  `replay`, `system`, and `scene`.

Tree-scale replay is an execution/simulation layer; the block/day MILP remains
the planning authority. FHOPS does not implement LiDAR segmentation.

### Ground-based multi-machine system

- `fhops.ground_system` links a feller-buncher, one or more skidders, one or more
  roadside processors, one loader, and a truck fleet in a deterministic
  event stream.
- Calibrated Han et al. (2018) skidder cycles and Barko 450 loader rates, with
  explicit `reference` fallbacks.
- TN-103, ADV5N6, and custom processor model/spec selection.
- Shift/day windows, staggered truck arrivals, landing inventory blocking,
  mill service bays, and deterministic or seeded stochastic downtime.
- Optional DEM sampling, grade refusal, single-corridor road routing, and small
  connected road-network shortest paths.
- CSV/JSON events, machine summaries, landing/mill inventory, and provenance.

### 3D output and example

- Deterministic `scene.gltf` / `scene.glb` export with procedural trees, ground,
  machine paths, log nodes, LOD, and camera keyframes.
- `examples/tree_system/` committed end-to-end example with a 12-tree synthetic
  stand, system event stream, glTF scene, and standalone viewer.
- Rendering/video remains external; FHOPS never embeds a renderer in core.

### Hydrology and documentation

- Phase 15 hydrology bundle consumption and Phase 16 flood-aware schedule
  checks are included from `main`.
- Phase 18 hydrology documentation/reproducibility work and its docs checks are
  included from `main`.
- See the P15/P16/P18 reports under `notes/reports/`.

## Compatibility and limits

- Existing 1.0/1.1 scenario contracts remain supported; tree inventories use the
  separate `fhops.tree.inventory.v1` contract.
- Tree data in the committed example and tests is synthetic. No real tree map,
  operational decision, or regulatory result is claimed.
- Stem volumes, products, and machine rates are reference models unless a
  reviewed local spec is supplied.
- Multi-machine simulation is one block, one landing, and does not model
  cross-block routing, adaptive dispatch, or full forest-road scale/landing
  search.
- DEM/road inputs and breakdown parameters must be reviewed for each use case.
- Web and LiDAR extras remain optional.
