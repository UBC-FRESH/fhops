FHOPS 1.0.1 is a maintenance release on the stable 1.0 line. It fixes defects found during the
SoftwareX manuscript revision and two pre-release audits. **Many fixes change results**: by strict
SemVer this would be 1.1.0. All comparisons below are with v1.0.0.

```bash
pip install fhops==1.0.1
```

> **`1.1.0a1` does not contain any of these fixes.** The tactical-layer alpha was released before
> this work. Because it has a higher version, `pip install --pre fhops` installs it instead of
> 1.0.1. Pin `fhops==1.0.1`.

### Results change — re-run these studies
- **Rolling horizon:** windows now carry state (remaining volume, staged inventory, role progress,
  machine positions, user locks, blackouts); v1.0.0 re-planned every block in every window. MILP
  windows break ties toward early production. `--mip-solver auto` (the default) now works and
  means HiGHS.
- **Stochastic playback:** per-landing-day shocks, sampled downtime durations
  (`--downtime-mean/--downtime-std`), and composing events. Results differ for the same seed.
- **Operational MILP formulation:** role output capped at block volume; staged inventory per
  upstream role; partial last truckload; **landing capacity enforced per shift slot** (the v1.0.0
  model never bound it); moves charged as in the KPIs; locks and blackouts enforced. Example: the
  tiny7 optimum is 279.796036 (v1.0.0: 4388.082752).
- **SA / ILS / Tabu:** the reported objective equals a fresh evaluation of the returned plan
  (v1.0.0 could overstate it when mobilisation was weighted); hard landing capacities are
  respected in every shift; the hard-violation penalty is no longer a flat 1000 (it scales with
  the largest production rate and move cost, so violations never pay); the ILS `--hybrid-use-mip`
  step is a real MILP warm start.
- **Playback/KPIs:** multi-shift assignment tables need `shift_id`. Empty plans report 0 delivered
  (v1.0.0 reported full delivery).

### Stricter validation — run `fhops validate`
Scenarios are cross-validated at load. Newly rejected: unregistered `harvest_system_id`; locks
outside the block window or with an incompatible machine role; unknown lock `shift_id`; invalid
`initial_state`. New optional fields `Scenario.initial_state`, `ScheduleLock.shift_id` and
`ScheduleLock.production` need `fhops>=1.0.1` (v1.0.0 silently ignores or misreads them).

### CLI and API changes
- **`fhops solve-mip` is deprecated.** It now solves the operational MILP; the legacy day-level MIP
  is infeasible for every system with a loader role. Output changed from `Objective: … Saved to …`
  to `MIP outcome=… solver_status=… termination=… objective=…|n/a`. Use
  `fhops solve-mip-operational`. `fhops build-mip` and `fhops.optimization.mip.solve_mip` are also
  deprecated.
- **MILP APIs return an `outcome` instead of raising** for infeasible models, time limits without
  an incumbent, or solver failures (`optimal|feasible|infeasible|no_solution|error`, plus
  `has_solution`, `solver_error`, `warnings`, `warm_start`). HiGHS warm starts (`--incumbent`)
  work. `solver="auto"` falls back from Gurobi to HiGHS.
- `solve-mip-operational` adds `outcome=` to its result line. `fhops plan rolling` has new flags
  (`--fail-on-no-solution`, `--mip-earliness`) and new exit codes, and its assignments CSV gains a
  `shift_id` column after `day`. `fhops bench suite` appends objective-weight columns.
- `fhops dataset` works with Typer ≥ 0.26 again. The SR-109 green-tree cost multiplier is
  corrected from 1.10 to 1.09.
- Dependency floors raised: `typer>=0.15.4`, `pyomo>=6.9.2`, `highspy>=1.8.1`, `PyYAML>=6.0.1`.
  `click` is no longer a dependency.
